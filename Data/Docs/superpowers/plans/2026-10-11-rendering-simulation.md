# DXR・大気・プロシージャル編集の実装計画

目的: 現在の `dev_dlss&raytracing` ブランチで、独自 DirectX 12 レンダラーに実ジオメトリのレイトレーシングを追加する。太陽の位置に連動する空と照明、地形と動きの生成・編集を既存エディターへ統合し、可読性と不要な毎フレーム処理を改善する。

## 実装単位と受け入れ条件

1. **DXR** — `source/rendering/raytracing.{h,cpp}` と compute shader に加速構造の所有権、構築、影・AOの評価を集約する。DXR Tier 1.1 / Shader Model 6.5 を判定する。実三角形の BLAS / TLAS を使用し、対応しない環境・無効設定・空のシーンでは既存描画を継続する。フレームごとの資源と GPU フェンスを守り、削除・再生成・動くジオメトリも安全に扱う。Deferred Lighting で主太陽の影と環境遮蔽へ適用する。UI は能力と実行状態を表示する。
2. **DLSS** — NVIDIA の公式 SDK を固定コミットで導入し、NGX の能力判定と実際の Super Resolution 評価を実装する。入力色・深度・動きベクトル・カメラのジッターを接続し、リサイズ・オン/オフ・HDR を扱う。SDK 未導入、非対応 GPU、無効設定では既存の Bilateral へ戻る。SDK のインストーラを用意し、SDK 本体は Git 管理へ含めない。
3. **大気と太陽** — 太陽の高度・方位から昼光、薄明、夜を連続的に計算する。24時間の時刻、緯度、季節、進行速度、朝・昼・夕・夜のプリセットを既存大気ウィンドウへ追加する。手動の Sun 位置でも空が変化する。既存の Rayleigh / Mie / volumetric fog と接続する。
4. **プロシージャル編集** — `source/procedural/` に deterministic な Perlin、value、Worley、fBm、ridged、domain warp の生成と地形メッシュを分離する。専用ウィンドウにプレビュー、seed、地形サイズ・解像度・高さ、生成・更新を実装する。選択した Entity に波・軌道・ノイズの動きを設定し、再生・停止・復元できる。設定保存・読込により同じ生成結果を再現する。
5. **整理と性能** — 全体の責務・依存・ホットパスを確認し、具体的な問題を修正する。primitive upload の重複、共有ジオメトリの加速構造、Sun 同期の単一 Entity キャッシュ、資源寿命・定数バッファ境界を重点確認する。既存のモデル・タイムライン・物理・保存契約を維持する。

## 検証

- 変更前 Debug ビルド・起動を記録する。
- 数学の CPU テスト: seed 再現性、ノイズ境界、地形の高さサンプル、日の出/正午/日没/深夜、時間の巻戻しと長時間進行、動きの停止と原点復元。地形メッシュは GPU smoke の生成・描画・再生成で確認する。
- 変更後 Debug / Release の C++ と HLSL ビルド、GPU smoke を行う。DXR / DLSS 有効・非対応時のフォールバック、地形生成・再生成・Undo/Redo、Sun プリセット、motion の Play/Pause/Stop、空の加速構造、終了、resize、HDR を実行する。
- 全ファイル登録と diff を確認し、実測の結果・未確認事項・操作方法を `docs/rendering-simulation.md` に残す。

変更はこのブランチの作業ツリーへ反映する。GPU依存の機能は CPU の検証をもって実機成功とは扱わない。
