# TSRの細部ちらつき抑制

Custom TSRの「細部のちらつき抑制」は初期値ON。入力TAAの追加は必要ない。OFFにすると前のTSRの蓄積・クリップ処理へ戻り、切り替え時は履歴を無効化する。この設定はセッション内だけで保持する。

## 原因と変更

20%入力では、1出力画素幅の線をジッター位相によって捉えないフレームがある。低解像度3×3近傍から線が消えると、従来の色範囲クリップが正当な履歴まで背景色へ切り詰めていた。

明暗の変化方向が繰り返し反転する細部を検出するため、出力解像度のRG16F履歴を2面追加した。Rは前フレームの再構成輝度、Gは変化方向付きの不安定度。3×3の既存参照を再利用し、局所コントラストを基準に細い明暗の筋を検出する。輝度が低い筋も対象とし、輪郭全般へ保護を広げない。

検出した細部では現在サンプルの混合量を抑え、近傍が平坦化したときだけ履歴クリップを緩める。移動が1出力画素/フレーム以上、深度不一致、画面外、Reactive Mask、全体履歴の無効化では保護を解除する。永続的な信号変更では不安定度を減衰させ、消えた模様が固定されないようにする。

手動露光もTSRの共通履歴判定へ渡すよう修正した。以前はCaptureの既定値1.0を使っており、露光値自体の変化を判定できていなかった。GPU自動露光の完全な履歴補償を追加したという意味ではない。

追加ディスパッチはない。RGBAの色履歴と出力アルファは保持し、不安定度を別リソースで管理する。履歴の画素データ量は出力幅×高さ×8バイトで、1920×1080なら約15.8 MiB増える。OFFでも比較用のリソースと初期値書き込みは残るため、OFF/ON比較だけで導入前からの全コストを測ったことにはならない。

## GPUシェーダー再現テスト

`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-temporalupscale.ps1`

実際のHLSLをGPUで実行し、補助履歴も本体と同じRG16Fで保持する。32×24から160×120へ拡大し、128フレーム蓄積後の32フレームを測定する。

| 測定対象 | 変更前 | 抑制ON |
| --- | ---: | ---: |
| 1出力画素幅の斜め細線：フレーム間RMS | 0.0345779 | 0.00377794 |
| 細線：解析的被覆率とのRMSE | 0.268182 | 0.204743 |
| 細線：背景からの平均コントラスト | 0.0174972 | 0.09528 |
| 通常の斜め輪郭：被覆率RMSE | 0.129386 | 0.129386 |
| 通常の斜め輪郭：フレーム間RMS | 0.0111251 | 0.0111251 |
| 低輝度の細線：フレーム間RMS | 0.00196027 | 0.000369969 |
| 低輝度の細線：被覆率RMSE | 0.0219715 | 0.0178561 |
| 低輝度の細線：平均コントラスト | 0.00118986 | 0.00597793 |

細線のフレーム間変動は約89%減り、線自体を消すことで安定化していないことも確認した。同じ深度のまま細線を消した場合、16フレーム後の最大残差は0.000393027。物体除去、カメラカット相当のリセット、Reactive Mask、移動輪郭について既存の検証も合格した。試作で生じた移動時の残像は、保護の適用条件を狭めてから再検証した。

低輝度テストは線の輝度0.1・背景0.02で、フレーム間変動は約81%減った。絶対コントラスト閾値を使った試作では低輝度テストが不合格となり、局所コントラスト基準へ変更後に合格した。同じ深度で線を消した16フレーム後の最大残差は0.000113975。

## 実アプリ検証の範囲

Debug/Releaseそれぞれ通常・DXR無効の描画検証を使い、20% TSR、履歴切り替え、ジッター進行、解像度切り替えを確認する。ログは`build/tsr-detail-{Debug,Release}.log`。

最終ソースでDebug/Releaseを再ビルドした後、局所コントラスト判定を含む最終HLSLでも通常・DXR無効の各84フレーム、計4通りが合格。Debugの両実行はD3D12エラー0件。手続き的編集976項目とシミュレーション2801項目も合格した。

添付されたキャラクターシーンの髪・刺繍・ハイライトでの動画比較と、フレーム全体のGPU負荷増分は未測定。上記の約89%は人工細線テストの値であり、実シーン全体の改善率ではない。高速移動中には保護を弱めるため、その状況でも同じ低減率になるとは主張しない。
