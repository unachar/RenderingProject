# `.noise` マテリアル

プロシージャルスタジオのテクスチャ設定を、画素ではなくバージョン付き JSON の `.noise` ファイルに保存する。マテリアルでは UV 座標で GPU の計算式を直接評価するため、PNG/DDS の保存解像度や圧縮率には依存しない。浮動小数点精度・画面の画素数・微分幅による限界はある。

## 使い方

1. プロシージャルスタジオのテクスチャ画面で模様を調整する。
2. 「.noise を保存...」からプロジェクトの `asset` フォルダ内に保存する。
3. アセットブラウザーからマテリアルの `Base Color`、`Normal`、`Height (POM)` にドロップする。
4. マテリアルを保存する。各入力欄には通常の画像も引き続き指定できる。例えば Base Color は PNG、Normal と Height は `.noise` にできる。1 つの欄ではいずれか一方を使う。

| 入力欄 | `.noise` の評価 |
| --- | --- |
| Base Color | スタジオの色設定を含むカラー |
| Normal | スカラー場の UV 勾配から接空間法線を生成。スタジオの法線強度とマテリアルの Strength を使用 |
| Height (POM) | スカラー場の高さ。既存の Parallax Depth / Steps、深度オフセット、セルフシャドウと共用 |

出力の Color / Height / Normal 選択はスタジオの画像プレビュー・画像保存用。`.noise` をどの欄に置いたかでマテリアル側の解釈が決まる。高さは白が上面、黒が奥。POM は既存と同じく不透明マテリアル専用で、Depth が 0 なら無効。

`.noise を読み込む...` で設定を復元できる。時間は保存時点の値で固定し、マテリアル側で自動再生はしない。再保存後のアセット更新で参照中のマテリアルを更新する。ファイル移動は通常のアセット操作で行い、`.meta` の GUID を保持する。

22 種類の基底ノイズ、フラクタル合成、レンガや幾何学模様など既存の GPU 生成対象に対応する。倍精度 CPU 計算を使う Mandelbrot / Julia の `.noise` 保存は無効にし、従来の画像保存を残している。未対応の式へ黙って置き換えない。

## 実装と検証

- 定義: `source/assets/noiseasset.*`。壊れた JSON・不正な列挙値・非有限数・過大な値・未対応の版を拒否し、読み込み失敗時は呼び出し元の設定を保持する。
- 共通評価: `shader/hlsl/ProceduralTexture.hlsli`。スタジオの GPU 画像出力も同じスカラー・カラー関数を使う。
- GPU パラメーター: 1 入力 208 バイト、3 入力で 624 バイト。既存 PBR 定数の先頭オフセットを保持して末尾に追加。マテリアル定数は 3040 バイト、GPU Scene レコードは 3136 バイト。
- 通常画像には従来の TextureManager を使う。`.noise` はテクスチャデスクリプターを消費しない。マテリアル・アセットのプレビュー、GPU 駆動描画、反射・GI カードの色にも定義を引き渡す。
- 通常画像のサンプリングより計算量が増える。特に高オクターブのノイズを POM に指定すると、レイの各ステップでノイズ計算が発生する。

CPU 回帰テスト: `python scripts/test-noise-materials.py`（C++20 コンパイラーが必要）。Windows の定義テスト: `powershell -File scripts/test-noise-assets.ps1`。

シェーダーのコンパイル: `python scripts/test-noise-shaders.py`（`DXC` にコンパイラーのパスを設定）。Windows の実 GPU / WARP 比較: `powershell -File scripts/test-procedural-gpu.ps1 -Warp`。この比較には全基底の細かい UV 位置での色・高さ・法線の CPU/GPU 比較を含む。

Linux で行った CPU テスト・DXC 検証は、Windows のアプリ全体のビルドや実機のドラッグ＆ドロップ・描画確認を代替しない。
