# 幾何スペキュラAAのGGX数値実験

実装が粗さを書き換えるだけの試験に加え、細いハイライトのサンプリング誤差を確認した。結論は条件付きで、低粗さでは誤差が減り、高粗さでは小さな誤差増加もあった。既定OFFは維持する。

`tests/geometric_specular_aa_quality_probe.cpp` は製品の共有 `FilterRoughness` を直接呼ぶ。幾何法線を `normalize(s*x,1,s*y)`、half vectorをY軸に固定し、標準GGX NDFを数値評価する。perceptual roughnessをr、alphaをr²とし、`D = r⁴(1+s²(x²+y²))² / [π(r⁴+s²(x²+y²))²]` と代数変形して小粗さでの桁落ちを避けた。

32通りのサブピクセル位相、7×7画素について、各画素内256×256 midpointサンプルの積分を参照値とした。AA入力の法線勾配は正規化した中心と隣接位置の前進差分。ONは共有式のscale0.15/threshold0.2、OFFは元の粗さを使う。誤差は全画素・位相の `sqrt(sum((sample-reference)²)/sum(reference²))`。

低粗さの点サンプルは、狭いピークを過大・過小評価しやすい。この場面では分散を足した粗さが積分参照に近づいた。一方、既に広いハイライトではフィルターのバイアスが増える。全粗さに対する改善率として宣伝しない。

中央の狭いピークについて256²対512²の積分差を別に確認した。8条件の相対差は最大2.83×10⁻⁶で、設定した1%基準内。ただしこれは中央の確認点だけであり、全画素・全位相の積分誤差の上限証明ではない。式・条件・結果CSVを保存し、実験は再現可能にした。

これはGGX NDFだけのCPU数値実験で、Fresnel/visibility/照明/normal map/背景/temporal reconstructionを含まない。7×7内の総量比は、BRDFのエネルギー保存や半球全体の積分ではない。前進差分はPS quad微分の全配置を再現するものでもない。32位相は実シーン動画のちらつき測定ではなく、このCPU実験ではFPSやGPU時間は測っていない。その後の[実レンダラーA/B](geometric-specular-aa-renderer-evaluation.md)では17組の画像と限定したDebug GPU時間を取得したが、時間方向の改善は示せなかった。両実験の結果を混同しない。

再現: `scripts/test-geometric-specular-aa.ps1 -QualityProbe`。同runnerの既存10,201ケースも合格し、新probeは `/W4 /WX /O2` でcompile・実行とも成功した。証拠は `bin/validation/technology/geometric-aa-quality-runner.log` と `geometric-aa-quality.csv`。後続の任意plot作成はmatplotlib未導入で失敗し、図は生成していない。数値probeの成功と図生成の失敗を区別する。
