# レイトレーシング・大気・プロシージャル編集

`dev_dlss&raytracing` ブランチの DirectX 12 / C++ エンジンに統合した機能と操作方法。
Unity プロジェクトではないため、Unity-GameDev から受け入れ条件・縦切り実装・実機検証の進め方を適用した。

## レイトレーシング

「ウィンドウ → レイトレーシング」で有効化と状態を確認する。
DXR Tier 1.1 と Shader Model 6.5 の能力を起動時に判定し、非対応環境では既存の描画を継続する。

- 実際の三角形から BLAS / TLAS を構築し、全ライトの影、主太陽の柔らかい影、環境遮蔽 (AO)、反射を描画する。
- Primitive、生成した地形、静的モデル、GPU スキニング後のアニメーションモデルに対応する。
- 同じ静的ジオメトリの BLAS を再利用する。動くモデルはフレームごとの資源で更新し、削除・地形の再生成・リサイズに追従する。
- サンプル数、影の距離、AO 半径、表面のオフセット、太陽の角半径を調整できる。
- 影を出す Sun は Physical / Directional、Active、CastShadow、AffectsOpaque が有効である必要がある。新しく作る Sun は影が有効。

環境設定でレイトレーシング全体・影・AO・反射・NRD を切り替える。対応 GPU で影を無効にすると影を消す。
不透明表面、透明モデルの受光、ボリュームの遮光は共通のシーン可視性を使う。ラスタの 8 灯分の影マップ上限は適用しない。
反射は画面外の三角形にも交差し、材質・テクスチャ・ライト・空を評価する一回反射。SSR は置き換えた。
透明な遮蔽物、屈折、多重反射、パストレーシングは含まない。
透明マテリアルと背景の Sky は加速構造から除外する。インスタンス上限は 16,384。
公式 NVIDIA NRD 4.17.3 の SIGMA で太陽の影、REBLUR_SPECULAR で反射、REBLUR_DIFFUSE_OCCLUSION で AO を時間方向にフィルターする。
点・スポット・面光源とボリュームの影は、三角形への確定的な可視性判定を使う。面光源の有限サイズの柔らかい影は対象外。
カメラ変更、リサイズ、無効化からの再開では履歴をリセットする。SDK がない場合は生のレイ結果で動作し、NRD 設定は無効になる。

別のチェックアウトでは `.\scripts\install-nrd-sdk.ps1` で固定コミット `792eff196afdd350fd9c3f862119017ccb438a0e` を取得し、静的 CRT 用の Debug / Release ライブラリと DXIL をビルドする。
SDK 本体は Git 管理外の `External/NRD/sdk/`。MSBuild の `/p:EnableNrd=false` で SDK を使わない構成を選べる。

## DLSS Super Resolution

公式 [NVIDIA DLSS SDK](https://github.com/NVIDIA/DLSS/tree/374959484e79a640feaba44c93ac8cfb0a03f5b5) の NGX API を使用する。
このマシンの RTX 3050 Laptop GPU では対応が確認できたため、実際の DLSS 評価まで実装した。
Frame Generation は対象外。

プロジェクト設定または描画設定の「アップスケーラー」で「NVIDIA DLSS Super Resolution」を選ぶ。
内部解像度 50% が Performance、約 59% が Balanced、約 67% が Quality の目安。
表示サイズより小さく、25% 以上の内部解像度で使用できる。
色・深度・動きベクトル・カメラのジッターから表示解像度へ復元する。HDR とトーンマッピングの変更時にも再初期化する。
SDK 未導入、非対応 GPU / ドライバー、内部解像度 100% または評価失敗時は Bilateral を使用する。理由は UI に表示する。

別のチェックアウトで SDK を導入する場合:

```powershell
.\scripts\install-dlss-sdk.ps1
```

固定コミット `374959484e79a640feaba44c93ac8cfb0a03f5b5` からヘッダー・静的 CRT 用ライブラリ・署名済みランタイムを取得する。
バイナリの SHA-256 と NVIDIA の署名を検証する。SDK 本体は `External/DLSS/sdk/` に置き、Git 管理には含めない。
ビルド時に SDK がそろっていれば自動的に有効になり、ランタイム DLL とライセンスを実行ファイルと同じフォルダーへコピーする。
SDK を使わない構成は MSBuild の `/p:EnableDlss=false` でビルドできる。

## 大気と時間帯

「ウィンドウ → 大気シミュレーション」を開く。
Sun がなければ「Sunを作成」で追加する。

1. 「有効」「太陽の位置から空を描画」を有効にする。
2. 手動で Sun を移動すると、太陽の高度と方位に合わせて空が変化する。
3. 時刻を使う場合は「時刻から太陽の位置を計算」を有効にする。「朝」「昼」「夕方」「夜」のボタンでも切り替えられる。
4. 「時間を進める」と「1日の長さ」で連続した昼夜を再生する。緯度と年の何日目かで季節も変えられる。

Rayleigh / Mie の単一散乱を積分し、青空、夕焼け、太陽の円盤、地球による遮光、夜空と星を描画する。
Sun の黄色い球メッシュを廃止し、既存の Sun も仮想の方向ライトへ移行する。選択・位置・時刻操作は維持する。
星の Seed と天球座標は昼夜で固定し、太陽の散乱光でコントラストを下げる。星の色、大小、銀河の帯、夜の大気光はプロシージャルに生成する。
太陽の色・強度、環境光、既存の霧も連動する。「編集画面でも時間を進める」で Play 中以外のプレビューを選べる。
Pause は進行を止め、Stop は Play 前の太陽と時刻へ戻す。

時刻は現地の太陽時として近似する。タイムゾーン・経度・天文暦による正確な日の出時刻の算出ではない。
雲、降雨、流体、複数散乱は含まない。

## プロシージャルエディター

「ウィンドウ → プロシージャルエディター」に地形・マップと動きのタブを追加した。

### 地形・マップ

| 手法 | 使い方の目安 |
| --- | --- |
| Perlin | 滑らかな丘 |
| Value | 値を補間する起伏 |
| Worley (Cellular) | セル状の地形 |
| fBm | 複数スケールを重ねた起伏 |
| Ridged fBm | 尾根や山脈 |
| Domain Warp | 座標をゆがめた複雑な地形 |

Seed、周波数、オクターブ、減衰、周波数倍率、Warp 強度、マップの幅、高さ、基準の高さを調整する。
ノイズのプレビューを見ながら「新しい地形を生成」を押すと、シーンにメッシュが追加される。
解像度は 4–256 セル。三角形数は `解像度 × 解像度 × 2`。
ヒエラルキーで生成した地形を選ぶと、そのパラメータを編集できる。「選択した地形をリアルタイム更新」で変更を自動反映する。
この設定は環境設定に保存する。無効にした場合も「選択した地形を更新」で再生成できる。大きな地形の連続編集は更新間隔を空ける。
生成・更新は Undo / Redo に対応する。

「設定を保存」「設定を読み込む」で `.proc` プリセットを扱う。初期パスは `Save/terrain.proc`。
同じ設定と Seed は同じ高さサンプルを生成する。不正なプリセットは適用前に拒否する。
生成対象は高さで表現する地形メッシュ。洞窟、道路、建物の自動配置、ノード式の汎用グラフは含まない。

### 動き

ヒエラルキーで対象を選び、「プロシージャルな動きを追加」を押す。
Wave / 波、Orbit / 軌道、Noise / ゆらぎを切り替え、各軸の振幅、周期/秒、Seed、原点を調整する。
「編集画面でプレビュー」でその場で確認できる。
「停止して原点へ戻す」「最初から再生」、Play / Pause / Stop に対応する。
対象を「メッシュ頂点」に切り替えると、Wave / Orbit / Noise で形そのものを動かす。空間周波数で模様の細かさを調整する。
元の頂点から GPU で現在・前フレームの位置と法線を生成し、描画、動きベクトル、レイトレーシングで共有する。無効化で元の形へ戻る。
Primitive・地形・静的モデルが対象。スキニング済みキャラクターとの重ね掛けは対象外。
物理を使う対象は Kinematic にする。Static / Dynamic の対象は物理の位置を優先し、プロシージャルな動きを進めない。

地形設定と動きは Entity の編集履歴・Play 前の復元へ統合した。
地形プリセットは `.proc`、大気・時刻・レイトレーシング設定は既存の `Save/project_environment.cfg` に保存する。

## 整理した処理

Mesh Shader Tier 1 の GPU では大きな静的・地形メッシュをメッシュレットで描画できる。通常 GBuffer と Visibility / Compute GBuffer の双方に対応する。
メッシュレットを視錐台・Hi-Z でカリングし、DispatchMesh は最大 65,535 グループずつに分割する。非対応 GPU は従来の頂点・インデックス描画を使う。
環境設定の切り替えと診断ウィンドウで経路・ディスパッチを確認できる。

- レイトレーシング、DLSS、太陽周期、ノイズ計算、メッシュ生成、設定の解析をそれぞれのモジュールへ分離した。
- 全体の描画・更新・保存の経路を確認し、Primitive の頂点アップロードの重複と Sun の単一 Entity キャッシュを整理した。
- ポストプロセスの定数をパス・フレームごとに保持し、後のパスが先のパスの値を上書きする問題を修正した。カメラ行列の逆行列計算もまとめた。
- Velocity は現在のカメラ定数を使い、見えている不透明な表面を深度判定して描画する。起動直後の不正な動きベクトルを防いだ。
- 深度の読み取りビューをリサイズ時にも更新し、Compute GBuffer の UAV 作成漏れと背景マテリアルの誤分類を修正した。
- 静的 BLAS とノイズプレビューをキャッシュし、不要な再生成を減らした。

既存機能との契約を保ち、問題のある経路を中心に整理した。全ファイルを一律に書き換えた変更ではない。

## 検証の再実行

```powershell
.\scripts\validate-rendering.ps1 -Configuration Debug
.\scripts\validate-rendering.ps1 -Configuration Release
.\scripts\validate-rendering.ps1 -Configuration Debug -NoDlssSdk
.\scripts\validate-rendering.ps1 -Configuration Debug -NoNrdSdk
```

C++ / HLSL ビルド、数学テスト、機能を有効にした 84 フレーム、DXR / DLSS を強制的に無効にした 84 フレームを実行する。
既にビルド済みなら `-SkipBuild`、フォールバックの再確認を省くなら `-SkipFallback` を指定できる。
SDK 無効で検証した後は SDK 無効オプションなしでビルドすると通常の構成へ戻る。
テスト中はユーザーの設定ファイルと ImGui レイアウトの自動保存を止める。
ログと朝・昼・夕方・夜・DLSS の画像は `bin/validation/<Configuration>-features/` と `-fallback/` に出力する。
SDK 無効の実行は `bin/validation/<Configuration>-no-sdk-features/` に分けて保存する。
`/Z7` は、この環境の PDB manager の不一致を回避する検証用設定。

## 初回機能実装の検証結果 (2026-10-11)

Windows / NVIDIA GeForce RTX 3050 Laptop GPU / Visual Studio 18・MSVC 14.51 で確認した。

| 検証 | 結果 |
| --- | --- |
| Debug / Release の C++・HLSL ビルド | 成功 |
| 数学の 2,785 チェック | 成功 |
| Debug / Release、DXR・DLSS 有効の 84 フレーム | 成功 |
| Debug / Release、DXR・DLSS を強制無効にした 84 フレーム | 成功 |
| Debug、NGX SDK を使わずにビルドした 84 フレーム | 成功 |
| DLSS 対応ビルドへ戻し、既存のユーザー設定で 12 フレーム起動 | 成功 |
| Debug の D3D12 ERROR / CORRUPTION | 0 件 |
| プロジェクトへのファイル登録・重複・diff の空白検査 | 問題なし |

GPU ではレイの実際の交差、有限な影・AO、地形の再生成と Undo/Redo、削除後の空シーン、ジオメトリの復元、
motion の Play/Pause/Stop、リサイズ、朝・昼・夕方・夜の描画、昼より暗い夜空を確認した。
DLSS は起動直後の有効化、オン/オフ、50%・約 67%・約 59%・約 33%・約 77%・25% の内部解像度、HDR 入力、トーンマッピングの切り替えで評価が成功した。
対応環境と強制無効の環境を合わせて、それぞれの機能テストの失敗数は 0。

Release は既存設定どおり D3D12 debug layer を有効にしていないため、GPU debug queue の検査は Debug で実施した。
最初の Release リンクで古い incremental LTCG の PDB が原因の LNK1318 が出たため、生成物 `.pdb` / `.ipdb` / `.iobj` を
`bin/validation/release-pdb-recovery/` へ退避して再リンクし、成功を確認した。ソースと最適化設定は維持した。
外部 ImGuizmo の C4244 と `/Z7` の D9025 は残っている。FPS の改善率を比較するベンチマークと手動の UI 操作テストは未実施。
