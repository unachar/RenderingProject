# Lumen方式GIの統合設計案

状態: DXRによる追加モードとして実装。検証結果は `lumen-integration-validation.md` を参照。
日付: 2026-10-19

## 目的と前提

既存のDirectX 12レンダラーに、Lumenの主要な設計であるサーフェスキャッシュとプローブベースのファイナルギャザーを追加する。動的な照明・材質・遮蔽物の変更を間接光へ反映し、画面外の物体からの寄与と反射内の間接光を扱う。UEのLumenソースを移植する計画ではなく、公開された技術説明を参考にする独自実装である。

参照: https://www.unrealengine.com/tech-blog/unreal-engine-5-goes-all-in-on-dynamic-global-illumination-with-lumen?lang=ja

既存のGIにはDXR、放射照度ハッシュキャッシュ、ReSTIR、NRD/OptiX、履歴破棄、GPU検証がある。これらをLumen実装済みとは扱わない。

## 選択肢

1. **推奨: DXRを利用するLumen方式の追加モード。** 既存TLASを利用し、サーフェスキャッシュ、照明更新、プローブギャザー、反射でのキャッシュ参照を新設する。既存GIとの比較と切替が可能。DXR Tier 1.1が必要。
2. **ソフトウェアトレースも含む構成。** 上記にメッシュSDF生成・保存、グローバル距離フィールド、更新・ストリーミングを加える。非DXR環境を対象にできるが、独立した大規模サブシステムが必要。
3. **既存GIの部分改善。** 現行キャッシュとReSTIRのみを調整する。変更は小さいが、依頼されたLumen方式の統合としては不十分。

以下は選択肢1の設計。性能目標の数値は未指定であり、既存GIとの同一条件比較で判断する。

## 処理構成

### サーフェスキャッシュ

新設する管理クラスが、メッシュ単位のカード割当、材質キャプチャ用アトラス、照明用の読み書き別アトラス、更新キュー、GPUリソース寿命を管理する。材質データにはベースカラー、法線、位置または深度、発光、有効性を保持する。

カードは複数方向から表面を表現する。カード範囲内という理由だけでヒットを採用せず、ヒット位置・深度・法線を照合する。対応できない面、複雑な内部形状、変形メッシュには、既存のヒット位置での評価をフォールバックとして使用する。未対応領域は可視化する。

現行のRaytracingGeometryには専用の永続IDがないため、カードの所有者IDとジオメトリ・材質の世代を定義する。TLAS内の一時的な並び順や再利用されるリソースアドレスのみを識別子にしない。

### 照明更新と多重反射

キャッシュ表面に直接光、発光、遮蔽を評価する。間接光は前フレームの確定済み照明から読み、更新先には書き込む。同一ディスパッチで未確定の更新値を読み戻さない。反射率とサンプリングPDFを適用し、発光・空の二重加算を防ぐ。

複数フレームで間接反射を伝播するため、照明変更後の遅延は測定対象とする。近傍・可視・変更されたカードを優先し、更新予算を設ける。古い照明が残る期間を診断情報に表示する。

### ファイナルギャザー

画面の深度・法線から低解像度のスクリーンプローブを配置し、複数方向へDXRでトレースする。ヒットではサーフェスキャッシュを参照し、未対応面は既存評価、ミスは既存の物理スカイを使う。

プローブの方向別放射輝度をフィルタリングし、深度・法線・可視性を考慮してフル解像度の放射照度へ再構成する。既存の合成側が期待する放射照度の単位を維持し、受光材質の拡散反射率/piは一度だけ適用する。

画面空間トレースは、自己交差・厚み・画面外判定の検証後に追加する最適化とし、最初の動作する経路の必須条件にしない。

### 反射と履歴

反射のヒット評価でも同じ確定済み表面照明を参照する。粗さ依存のフィルタリングと、未対応面の既存評価を保持する。GIと反射で発光や空を重複加算しない。

モード変更、リサイズ、カメラカット、ライト・材質・ジオメトリ・空の変更について、キャッシュとギャザー履歴の無効化を明示する。静止カメラでの照明変更も検出する。GPUフェンス前にカードやアトラス領域を再利用しない。

## 既存コードとの接続

- `source/rendering/renderersettings.h`: 新モードと設定。既存のOff/ScreenSpace/Realtimeの保存値を維持する。
- `source/rendering/raytracingscene.h` と収集処理: キャッシュ所有者と更新世代の取得。
- 新しい表面キャッシュ・ギャザー用C++/HLSL: リソース、更新、トレース、再構成を分離する。
- `source/rendering/rayreflections.cpp` と `shader/hlsl/RayReflectionsCS.hlsl`: 共有シーンとの接続、反射での照明参照、既存GIとの排他的な出力選択。
- `source/editor/editorsettings.cpp`: モード切替、設定保存、カバレッジ・照明・更新状況の表示。
- `source/rendering/performancegovernor.h`: 新モードの予算調整とフォールバック。
- `DirectX12.vcxproj` とシェーダービルド定義: ソース登録とインクルード依存。

現行のReSTIRリザーバーはピクセル単位の契約なので、プローブへそのまま流用しない。新経路ではまず独立した推定器を成立させる。現行のワールド放射照度キャッシュも、サーフェスキャッシュと同じデータ構造として扱わない。

## 実装・受け入れ順序

1. 表面キャプチャ、カバレッジ表示、変更検出を実装。材質・発光・変換の編集、カード再割当を確認する。
2. 直接照明と読み書き分離した間接照明更新を実装。閉じた部屋で色移り、空の遮蔽、二次反射の寄与を確認する。
3. プローブギャザーと再構成を接続。画面外の発光、カメラ移動、薄壁、遮蔽解除、モード切替を確認する。
4. 反射へ同じ照明を接続し、設定保存と性能調整を統合する。
5. 必要なら画面空間トレースを追加し、DXRのみの結果との誤差・負荷を比較する。

各段階で動く縦切りを作り、単なる新モード名の追加を完了としない。

## 検証

既存の `scripts/validate-gi.ps1` と `scripts/measure-temporal-lighting.ps1` を既存モードの回帰確認に用いる。新モードには専用のGPUフィクスチャを追加し、HDR出力を読み戻して次を比較する。

- 同一照明の直接光のみ・既存GI・新GI、および二次反射の有無。
- 画面外の寄与、照明色変更、発光停止、移動遮蔽物、材質編集への追従。
- カメラ移動・カット・リサイズ・モード切替後の古い光と不正値の残留。
- キャッシュ未対応面のフォールバック、カード境界、薄壁の光漏れ。
- 反射内の間接光と、発光・空の二重加算の有無。
- CPU/GPU時間、レイ数、VRAM、更新遅延、時間方向RMS。小規模フィクスチャと実シーンを分けて報告する。

Debug/ReleaseのC++と該当HLSLをビルドし、D3D12検証エラーを確認する。閾値はシーンの基準測定から明示して設定する。設計段階ではビルド・GPUテストは未実行。

## 初期範囲外

メッシュSDFとグローバル距離フィールド、非DXR経路、透過・ボリュームへのGI、UEとの画質・機能の完全一致はこの推奨案に含めない。現行レイシーンの不透明交差という制約は残る。これらが必須なら、実装前に選択肢2または別の設計へ範囲を変更する。
