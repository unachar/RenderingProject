# fastgltf integration

Goal: Implement the installed glTF parser as a model import backend and compare complete equivalent import work with existing Assimp. Parsing JSON alone is not an adequate adoption benchmark.

Use an owning aiScene adapter so existing material, mesh optimization, GPU upload, animation and release contracts remain available. Confirm Assimp's release ownership contract before handing it generated scenes. Preserve glTF nodes/transforms, indices/topology, vertex attributes, textures/materials, skin and morph data; handle supported extensions explicitly and retain existing import when the new backend cannot preserve required semantics. Coordinate conversion and postprocessing must match each production caller.

2026-11-01 progress: `scripts/build-fastgltf-dx12.ps1` built and installed Release static SDK plus simdjson 5.0.4 / simdutf 9.2.1. Upstream dependency downloader verified its specified SHA256 values. Initial sandbox DNS failed; the authorized desktop retry downloaded them successfully. CMP0091 must be NEW for the requested static CRT to take effect; the script now sets it and a subsequent build succeeded. Debug SDK and product linkage remain pending. Upstream CMake identifies fastgltf as 1.0.0 while the vendoring manifest says 0.9.0/main; do not infer release identity from that manifest label. License packaging must include parser dependencies before product distribution.

`scripts/test-fastgltf-sdk.ps1` links the Release static libraries and loads existing Box.glb (24 positions, 2 nodes) and TriangleWithoutIndices.gltf (3 positions, 1 node), decoding finite positions with the actual accessor iterator. Both pass (`bin/fastgltf-sdk-probe.log`). This is an SDK availability/ABI probe only: it does not implement the scene adapter or establish semantic parity, importer speed or a default selection.

Draco mesh decoding is now integrated and compared in `docs/draco-comparison-2026-11-01.md`. KTX2 glTF texture extension contracts still require explicit integration and are not proven by basic fastgltf parser support.

Ruling: use a separate Release adapter DLL for both application configurations. The initial static integration mixed Debug iterator layouts inside one executable; CPU fixtures compiled with the same override failed to reveal the hazard, while product startup crashed through both importer selections. Do not suppress iterator mismatch in the application. The adapter's public boundary has only raw pointers, integral values and caller-owned error buffers; all SDK ownership remains in its DLL. Build with `scripts/build-fastgltf-dx12.ps1` followed by `scripts/build-fastgltf-adapter.ps1`.

Core conversion now includes hierarchy/matrices, triangle/indexless geometry, normalized colors/UV/tangents, basic PBR materials/images, skin, static morphs and linear TRS animation. Tests compare actual StaticModel/AnimationModel postprocess flags as well as no flags. Sparse fixtures compare against their known dense equivalents because this bundled Assimp misreads the interleaved sparse fixture. Unicode/percent-escaped external buffers exercise native failure recovery. Release, normal Debug consumer and SDK-disabled tests pass through the final DLL boundary.

DLL-version product Debug build, normal Debug/Release consumers and SDK-disabled tests pass.
