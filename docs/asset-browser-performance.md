# アセットブラウザの読み取りと描画（2026-10-26）

## 確認した負荷

以前の一覧更新は、UIスレッドで0.5秒ごとにフォルダを列挙し、並べ替え、
表示用の文字列を組み立てていた。検索変更もファイルの再列挙を発生させ、
登録済みハンドルを破棄するため、表示中のアセットの `.meta` を繰り返し読み直していた。
サムネイルのメッシュ解析自体は既に非同期だったが、ディスクキャッシュの確認は
Assimpによるモデル全体の解析と頂点展開の後に行っていた。
これらは実装上確認した負荷であり、元のフリーズを計測して単一原因に絞った結果ではない。

## 変更

- `AssetBrowserListing` が列挙、種別判定、並べ替え、名前の変換をワーカーで実行する。
  UIは完成したスナップショットだけを受け取り、古いフォルダの結果を破棄する。
  同時に走る走査は1件に制限する。
- 既存の0.5秒間隔の外部変更確認を維持し、内容が変わらなければ一覧とハンドルを再利用する。
  `.meta` の更新時刻も監視し、GUID変更や不正なメタデータの修正を反映する。
  登録失敗もスナップショットの変更か明示更新まで記憶し、毎フレームの再読込を防ぐ。
- 検索は取得済みの名前だけで絞り込む。描画は既存の行クリッパーを維持し、
  可視セルの名前、パス文字列、フォルダ種別を再利用する。
- メッシュ用のキャッシュ情報にソースパス、生成条件、外部依存ファイルとその版を保存する。
  有効なDDSがあればAssimpを呼ばずに復元する。移動、モデル変更、任意名MTL、
  glTF外部バッファ、テクスチャの変更は再生成につながる。古い形式や壊れた情報は再生成する。

## 検証

```powershell
./scripts/test-asset-browser.ps1 -Configuration Debug
./scripts/test-asset-browser.ps1 -Configuration Release
./scripts/test-thumbnails.ps1 -Configuration Debug
./scripts/test-thumbnail-mesh-io.ps1 -Configuration Debug
./scripts/measure-build.ps1 -Configuration Release -Target Build -BuildNodes 1
./scripts/validate-thumbnails.ps1 -Configuration Release -TimeoutSeconds 420
```

一覧テストは1,500件、走査中の移動、更新、フォルダ消失、メタデータ変更を対象とする。
キャッシュ情報のテストは条件変更、依存ファイル変更、モデル移動、不完全・旧形式の情報を扱う。
GPU検証はキャッシュ復元時にメッシュ頂点を生成しないこと、外部MTL変更、選択、
1,000件でのクリッピング、サイズ変更に加え、実プロジェクトのルートへの移動を確認する。
ルート検証はサムネイルが完了または失敗の状態になるまで描画を続け、少なくとも60フレームを確認する。
CPUフレーム時間はアプリ全体の測定であり、ディスクの初回読込や他の環境の上限を保証しない。

実GPU結果は `build/thumbnail-tests/validation-Release.log`、ルートの表示画像は
`build/thumbnail-tests/browser.png`。ReleaseではD3D12デバッグレイヤーを有効にしていない。
この変更でDebugアプリのGPU検証や、ネットワークドライブでの遅延検証は行っていない。

同日の最終GPU検証は正常終了し、失敗件数は0。実ルートの対応アセット1件を含む
60フレームでは、アプリ全体のCPU処理時間の最大値は23.484 msだった。
先行検証は13.636 msで、処理時間には実行ごとの差がある。
起動・終了を含む検証全体は4分制限に達することがあったため、再実行では420秒を指定した。
ルートの測定は検証用サムネイルを生成した後に行い、初回シェーダーコンパイルを含む
完全なコールドスタートの停止時間は測定していない。
